# デザイン仕様 v2.4 追補: 連携（コンボ後の行動と分岐の木）

Designerの設計（2026-10-16）にManager側の確定事項を反映したもの。データ方針は D-021（`parentId`、深さ3、子8個、schemaVersion 3）。UIの決定は D-022。

## 0. 確定事項

- ユーザー決定: 分岐は木構造（コンボ → 連携 → 分岐 → 分岐の分岐、3段）。連携も記録数に数える（キャラ選択の件数・ネオン段階・読み上げ名）。複数のコンボから同じ連携を参照する仕組みは作らない。
- Managerの決定（Designerの確認事項への回答）:
  1. 連携の欄は、コマンド列の直下（メモの上）に置く。
  2. 兄弟の並べ替えは作らない。兄弟の順序は `position`（兄弟の中での順序。新規は兄弟の最後）で持つ。画面は `position` の昇順、同じなら `createdAt`、さらに `id` の順。Designer案の「createdAt順」は、この規則に置き換える（将来の並べ替えにデータの変更が要らない）。
  3. セクションの帯の件数は、見えている行（根）の数にする。削除シートのラジオの件数も根の数。キャラ選択・ネオン・読み上げ名の件数は全件（連携・分岐を含む）。
  4. 子孫のある根を消すときも、確認シートを出す（取り消しも出す）。子孫のない根は今のまま確認なし。
  5. 子の位置・セクションは、編集画面に出さない。新規作成時に親の `sectionId` を写し、`position` は兄弟の最後にする。
  6. 迷子（親が見つからない・循環・深すぎる記録）は、`validateDoc` が拒否するので通常は起きない。画面側の防御として、迷子は根として一覧に出す（データを隠さない）最小の処理を入れる。
  7. 初めから開くのは1段目と2段目。3段目は閉じて始める。
  8. 一覧の「連携 N」は直接の子（連携）だけを数える。
  9. 1段目の記号 A〜H を付ける。
  10. 親が消えた子の下書きは、残したままにする（掃除しない）。
  11. 今回作らないもの: ノード単位の複製・移動、ノードのお気に入り表示、全部を開く・閉じるボタン、ノードごとの［＋分岐］ボタン、兄弟の並べ替え。
- 連携・分岐のコマンド列は、親のコマンド列と切り離して技名を判定する（先頭の派生は技名なし。既知の限界）。

## 1. 方針

- 木はカードにせず、細い線と字下げで、コンボから枝分かれさせる。線は `--line-strong` の1pxだけ。発光・新しい色・新しい形は足さない。
- ▶ は木の線に使わない（`i-conn` の▶はコマンド列の中の「つなぎ」の意味。同じ形に2つの意味を持たせない）。枝は線（├ └）で描く。
- 連携も分岐も同じ「ノード」で描く。違いは、字下げの深さ、見出しの記号（1段目だけ A〜H）、初めから開くかどうかの3点。
- 読み上げは入れ子の `<ul>` と見出しの階層（h3/h4/h5）。`role="tree"` は使わない（矢印キーの移動の実装が要り、treeitem の中のボタンが読み上げで届かない恐れがあるため）。
- 動きは足さない（折りたたみは即時）。

## 2. 詳細画面（`#/c/:cid/r/:rid`）

並び: メタ → タイトル → ダメージ → コマンド列（今のまま）→ **連携の欄（新規）** → メモ。下部バー（［その他…］［複製］［編集］）は変えない。

### 2.1 連携の欄 `section.t-sec`
- 上端に1pxの `--line` の罫線。見出しの行 `.t-sec-head`（高さ44以上）: `h2.t-sec-h`「連携」（13px、muted）、件数 `.t-sec-n`「3件」（12px、muted。0件は「なし」）、右端に副ボタン［＋ 追加］（`.btn`、高さ44、`aria-label="このコンボに連携を追加"`、`data-fk="add-link"`）。
- 0件のときは、この1行だけを出す。
- 連携が8件のとき、［＋ 追加］に `aria-disabled="true"`（opacity .4、フォーカスは受ける）。押すとトースト「連携は1つのコンボに8個までです」（3秒）。
- 読み取り専用（`loadError`）のときは［＋ 追加］と各ノードの［…］を出さない。折りたたみは使える。

### 2.2 木の構造（DOM）

- 兄弟の順序は 0章2の規則。1段目の記号は順番どおり A〜H（`String.fromCharCode(65+i)`、Tilt Neon 15px、muted）。2・3段目は記号なし（数字表記の設定でコマンドの「1」と見間違えるため、数字も使わない）。
- 見出しが空のとき: 1段目は「A」＋muted 400 の「見出しなし」、2・3段目は muted 400 の「分岐1」（兄弟の中での順番）。
- 技名の判定は、ノードごとに `specialNames(node.tokens, cid)`（親とは切り離す）。チップを押すポップオーバーは根と同じ `onChip`/`canTap`。

### 2.4 折りたたみ
- 初めから開くのは1段目と2段目。3段目は閉じて始める。
- `button.t-fold`（`aria-expanded`、`aria-controls="t-list-<id>"`、`data-fk="fold:<id>"`）。中身は、閉じているとき `i-chev` 0°、開いているとき90°の16px（fg）と「分岐 2件」（13px、muted）。
- 閉じた子の木はDOMを作らない。押したら `render({ keepScroll:true, focus:['fold:<id>'] })` で描き直す。
- 状態は保存しない（モジュール変数 `treeOpen = new Map()`）。追加・編集から戻ったときは、そのノードの祖先をすべて開く。

### 2.6 ノードの操作（［…］のシート。`openSheet` と `menuItem`）
- シートの見出し: 1段目「連携A 投げ重ね」、2・3段目「分岐 ガード時」。

- 並べ替え・ノード単位の複製と移動は置かない。

### 2.7 件数が多いとき
3段目が閉じて始まるので、最初に描くのは最大 8＋64＝72 ノード（すべて開いて584）。仮想化はしない。データの不整合で兄弟が9件以上あるときも全件を出し（記号は I、J…）、追加は無効にする。

## 3. 追加・編集・削除

### 3.1 ルート
| 用途 | ハッシュ | 要点 |
|---|---|---|
| 連携・分岐の新規作成 | `#/c/:cid/new?p=<parentId>` | `parseRoute` の new に `pid`。`p` があれば `s` は無視 |
| 編集 | `#/c/:cid/r/:id/edit`（今のまま） | `rid` が子でもそのまま開く |
| 子のidの詳細 | `#/c/:cid/r/:childId` | `redirectFor` で根の詳細へ `replaceState` し、`node:<childId>` にフォーカスして祖先を開く |

`redirectFor` に足す条件: p の親がない・別キャラ → 一覧へ。p の親が3段目、または子が8個 → 根の詳細へ移し、トースト「分岐は3段目までです」または「分岐は8個までです」。

### 3.2 編集画面（`editScreen` を再利用。パッド・R1・［完了］・格納バーは変えない）
- 上部バーの h1: 新規は、親が根なら「連携を追加」、親が1・2段目なら「分岐を追加」。編集は、1段目なら「連携の編集」、2・3段目なら「分岐の編集」。戻るボタンの `aria-label="コンボの詳細に戻る"`、戻り先は根の詳細。
- **「つなぐ元」の欄 `.parent-ctx`**（`main` の先頭、下書きの時刻の上、`tabindex="-1"`）: 1行目に「つなぐ元」（12px、muted）＋親の名前（13px/700、fg、1行で省略。根ならタイトル（空なら「無題のコンボ」）、1段目なら「連携A 投げ重ね」、2段目なら「分岐 ガード時」）。2行目に親のコマンド列を `.preview`（S寸法、1行、段階に追従）。CSS: `margin: var(--s2) var(--s4) 0; padding-bottom: var(--s2); border-bottom: 1px solid var(--line);`。高さ約63px。360×740でパッドの上端326より上に収まる（要実測）。
- 入力欄（子のとき）: 見出し → ダメージ → タグ → メモ。セクションと位置は出さない。見出しのラベル「見出し（任意）」（`id="f-title"`、上限100字）、placeholder は連携「例: 打撃重ね／投げ重ね」、分岐「例: ガード時／ヒット時」。新規作成のとき `sectionId` は親の値を写し、`position` は兄弟の最後（データ層の関数）、`favorite` は false。
- ［完了］のフォーカス先: 根は今の `#f-sec`、子は `.parent-ctx`。
- 根の編集画面: 子孫があるときだけ、セクションのセレクトの下に「連携・分岐 5件も一緒に移ります」（12px、muted、`id="f-sec-hint"`、セレクトの `aria-describedby`）。
- 保存: 保存の直前に、親がまだあること、段の上限、8個の上限を調べ直す。違反なら画面を移らず `errorBox`（見出し「保存できませんでした」、本文は2文（分岐は8個までであること、ほかの分岐を消せば保存できること。入力内容は画面に残る旨も添える）。親がないときは本文を「つなぐ元の記録が見つかりません」で始める）。成功したら根の詳細へ戻り、トースト「保存しました」。戻り方は、`navN>0 && prevHash === 根の詳細` なら `history.back()`、それ以外は `replaceState`（同じ詳細が履歴に2つ積まれない。`removeCombo` と同じ判定）。戻ったら保存したノードの［…］にフォーカスし `scrollIntoView({block:'center'})`（`focusUndo` と同じ形のモジュール変数で渡す）。
- キャンセル: 戻るボタン（`goBack`）。保存しないで戻ったら、今と同じく「下書きを残しました」。
- 下書き（`sf6memo.drafts`）: 新規の子のキーは `child:<parentId>`（`new:<sectionId>` と衝突させない）。中身に `parentId` も持たせ、`sanitizeDraft` は文字列だけ受け付け、開いたときにキーの親と一致しなければ捨てる。子の編集は今の `edit:<id>`。親が消えた子の下書きは残す。

### 3.3 追加の置き場所
連携: 連携の欄の見出しの行にある［＋ 追加］。分岐: ノードの［…］→「分岐を追加」。

### 3.4 削除
- ノード（子孫なし）: 確認なしで消し、`mutate` で取り消しのトースト「『ガード時』を削除しました［元に戻す］」（見出しが空なら「連携A」または「分岐」）。フォーカスは［元に戻す］へ、取り消し後は `node:<id>` に戻す。
- ノード（子孫あり）: 同じシートの中身を確認に差し替える（`deleteSheet` と同じ形）。見出し「『投げ重ね』を削除」、本文（`.note`）「この連携の下にある分岐 3件もまとめて削除。削除のあと6秒間は［元に戻す］で戻せる」、主ボタン［削除］。実行後のトーストは「『投げ重ね』と分岐3件を削除しました［元に戻す］」。取り消しは全件が元どおり（`prev` を書き戻す）。
- 根（子孫あり）: ［その他…］→［削除］で同じ形の確認。本文「このコンボの連携・分岐 5件もまとめて削除。…」（前項と同じ構成）、トースト「『タイトル』と連携・分岐5件を削除しました」。そのあとは今の `removeCombo` と同じく一覧へ。子孫のない根は今のまま確認なし。

### 3.5 複製・移動
- 根の複製: 子孫も新しいidで複製し、`parentId` を新しいidに付け替える。子の `createdAt` と `position` は元の値のままにし、`updatedAt` だけ now にする。トースト「複製しました（連携・分岐 5件を含む）」。
- 根のセクション移動とセクション削除の移動: 子孫も同じ `sectionId` に移す（データ層）。表示は `parentId` だけで決め、子の `sectionId` は表示に使わない。

## 4. 一覧と件数
- 一覧の行は根（`parentId` なし。迷子を含む）だけ。連携があれば `.item-meta` の `.dmg` の左に `span.lnk`「連携 <b>2</b>」（直接の子だけ。0件なら出さない）。CSS は `.dmg` の規則に `.lnk` を並べる（`.dmg, .lnk { flex:none; white-space:nowrap }`、`.dmg b, .lnk b { …--ms-ldmg… }`）。読み上げは中の文字のまま。360pxの幅配分は「連携 2」約40、ダメージ約85、残りが `.meta-t`（省略表示）。
- セクションの帯の件数「N件」と削除シートのラジオの件数は、根の数。
- キャラ選択の `aria-label` の件数、`data-lv`、一覧のワードマークの段階は、全件（連携・分岐を含む）。見た目は変えない。
- 最近の技（R1）とタグの候補は、連携・分岐の技とタグも含む。取り込みの確認の件数は連携・分岐を含む（文言は変えない）。
