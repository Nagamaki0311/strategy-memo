# デザイン仕様

注: ネオン街モチーフへの刷新（v2）は docs/design-spec-v2.md にあり、v2に書かれた章はv1に優先する（D-012）。

Designerが作成した仕様（2026-10-15）に、Manager側の確定事項（D-005、D-010、ユーザー回答）を反映したもの。Developerは本書に従って実装する。デザイントークンはT-007でCLAUDE.mdへ短い節として記録する（docs/design-workflow.mdの手順）。

## 1. 方針

- 制作物はスマホアプリ（Android ChromeのPWA、縦持ち360〜430px）。優先する要素はタッチ操作、片手操作、入力速度、情報階層、画面遷移。
- 視覚方針は「練習ノート／譜面」。コマンド列を、左から右へ読み、技の単位で折り返す譜面として扱う。行は罫線で区切り、カードにしない。枠で囲むのは、意味の上でキーやチップである物だけ。
- 色を持つのは「ボタン強度」と「OD」だけ。他のUIは墨と生成りの無彩色で作る。主ボタン、エラー、選択状態にも色相を使わない（形・反転・線で区別する）。
- テーマはダーク1種類に固定する（ユーザー確認済み）。`<meta name="color-scheme" content="dark">`、`theme_color`と`background_color`は`#16140F`。理由: 強度色は明るい淡色で、暗い地なら円が地に対して8.5:1以上で浮き、グレースケールでも●の形が読める（受け入れ基準7.3-7）。トレーニングモードの横で見てもまぶしくない。検証が1テーマで済む。
- 影・グロー・グラデーション・すりガラス・カードは使わない。重なりは面の明度差、1pxの罫線、背面の暗幕で示す。
- アプリ名は「SF6戦略メモ」（manifestの`name`）、`short_name`は「戦略メモ」。

- 余白: `--s1` 4、`--s2` 8、`--s3` 12、`--s4` 16、`--s5` 24、`--s6` 32（px）。画面の左右余白は16px、パッドのみ左右6px。

## 3. チップの文法（requirements 3.3）

### 共通

- 記号はすべて`index.html`に1回だけ置くインラインSVGスプライト（`<symbol>`）を`<use>`で参照して描く。Unicodeの▶・↓・↘などは画面描画に使わない（Androidで絵文字化することがある）。コピー・書き出しのテキストではUnicodeを使う。
- 通常技・必殺技のチップは枠も塗りも持たず、記号同士の間隔でまとまりを示す。枠を持つのはシステム技・SA、待ち・移動のみ。

### 寸法

| 部品 | L（詳細・編集） | S（一覧・直近8件） |
| --- | --- | --- |
| ●の直径 | 34 | 24 |
| 矢印の箱（線幅） | 22（3.5） | 15（2.5） |
| システム技チップの高さ（文字） | 34（15px／700） | 24（12px／700） |
| CH・PCタグの高さ | 20 | 16（文字は12px／700） |
| ▶（左右の余白） | 8×10（10） | 6×8（6） |
| チップ内の間隔 | 2 | 1 |

タップ領域はLで最小44×44（見た目34に透明のpaddingを足す）。一覧の行は行全体がタップ対象。

### SVG

- ●: `viewBox 0 0 36 36`、`circle r=18`、強度色で塗る、輪郭線なし。Pのパス`M13 27V9h6a5 5 0 0 1 0 10h-6`、Kのパス`M12 9v18 M24 9L13 19 M16.5 16L24.5 27`。いずれも`stroke=var(--ink)`、`stroke-width 4`、`stroke-linecap square`、`stroke-linejoin miter`、`fill none`。
- 矢印: `viewBox 0 0 24 24`に右向きを1つだけ描く（軸`M3 12H15`、`stroke-width 4`、`butt`。矢じり`polygon 13,5 22,12 13,19`）。8方向は`rotate()`で作る。色は`--fg`。
- ▶: `polygon 0,0 10,6 0,12`、塗り`--conn`。軸がなく、小さく、灰色。矢印とは形・大きさ・明度で区別する。

### 種類ごとの構成（左から順）

| 種類 | 構成 | 例 |
| --- | --- | --- |
| 立ち通常技 | ●のみ | `●P` |
| しゃがみ通常技 | ↓矢印＋● | `↓●K` |
| ジャンプ通常技 | 「J」＋● | `J●K` |
| 方向入れ通常技 | 方向矢印＋●（姿勢との併用は「J」→矢印→●） | `←●P` |
| 必殺技 | モーションの矢印列＋●（間に＋を描かない） | `↓↘→●P` |
| 溜め | 溜める方向の矢印を角括弧`[ ]`（`--fg`、線幅2.5）で囲む＋続く矢印＋● | `[←]→●P` |
| 360 | 270°の開いた円弧と矢じり（太線、`--fg`、塗りなし）＋●。8矢印を並べない | `↻●P` |
| OD必殺技 | モーション＋「OD」＋●2つ | `↓↘→ OD ●P●P` |
| システム技・SA | 角丸の文字チップ | `[CDR]` `[DI]` `[SA3]` |
| 注記CH・PC | 小さなタグ。直後の技に付く | `CH ↓↘→●P` |
| 待ち・移動（Phase 2） | 点線枠の文字チップ | `[ディレイ 3F]` |
| 未認識（Phase 2） | 「」付きの生の文字列＋波線の下線 | `「xx9」` |

### 細則

- 「J」は素の文字（15px／700、`--fg`）。「OD」は素の文字（15px／700、`--od`）で、ODの●2つは`--od`で塗り強度を持たない。2つ目は-8pxずらして重ね、`--bg`色の2px輪郭で分ける。●の前に付く素の文字は、その●の修飾とする。
- 溜めはaria-labelで「←溜め→」と読み上げる。360の円弧は塗りも文字も入れない（●と混同させない）。
- システム技・SA: 高さ34、左右padding 10、`--r-chip`、2pxの実線枠（`--fg`）、塗り`--key`、文字`--fg`。
- 注記タグ: 枠なし、塗り`--line-strong`、`--r-tag`、文字12px／700。CH・PCと次の技の間には▶を入れない（▶はタグの前に入る）。
- 待ち・移動: 2pxの破線枠（`--fg-muted`）、`--r-chip`、塗りなし、文字14px／700。
- 未認識: 生の文字列を「」で囲み、`--fg-muted`、`text-decoration: underline wavy`。この語に限り`word-break: break-all`を許す。aria-labelは「未認識: xx9」。詳細画面に「未認識の語が1件あります」を1行表示する。
- 強度の補助文字（設定、既定オフ）: ●の右下に15×15の角丸2の四角いバッジを半分はみ出して置く。塗り`--ink`、文字「弱／中／強」11px／700、`--fg`。ODの●には付けない。
- 方向5（ニュートラル）: 素の文字「N」（`--fg`、Lは15px／700、Sは12px／700。「J」「OD」と同じ扱い）を、矢印と同じ幅の箱の中央に置く。aria-labelは「ニュートラル」。数字表記モードでは「5」。
- 数字表記モード: 矢印列を「236」の文字（`--fg`、18px／700、tabular-nums）に置き換える。しゃがみの↓は「2」、溜めは`[4]6`、一回転は`360`。●・▶・チップの形は変えない。
- 折り返し: コマンド列は`display:flex; flex-wrap:wrap; row-gap:6px`。1つの技（モーション＋●、CH＋技）は`inline-flex; flex-wrap:nowrap`の1グループにする。▶は直前のグループの末尾に含める（行は▶で終わってよいが、▶で始まらない）。
- 一覧の行のプレビュー（S）: `flex-wrap:wrap; height:28px; overflow:hidden`。入りきらないチップは非表示の2行目へ回るので技が途中で切れない。メタ情報に「全N手」を出す。

### 色を除いたときの区別（受け入れ基準7.3-7）

● 塗りのある円／矢印 軸のある線／360 塗りのない円弧／▶ 軸のない小さな三角／システム技 実線枠の角丸箱／注記 枠のない小さな灰色の箱／待ち・移動 破線枠の箱／J・OD 素の文字／未認識 「」と波線。同じ形を2つの意味に使わない。

## 4. パッド（編集画面の下部）

### 寸法（360×740）

下段ブロック: 方向3×3（44×3＋間隔4×2＝140幅）、左右の溝12、右側の列196（4列×46＋間隔4×3）、3段×48＋間隔6×2＝156高。システム行は「頻度順の横スクロール1段」とする（ユーザー確認済み）。CDR・生ラッシュ・DI・SA1〜SA3の6個（幅計332）は常に見え、7個目（DP）は端が16pxのぞいてスクロールできることを示す。DP・Dリバ・CH・PCはスクロールして押す。検算用の9タップ（CDRを含む）はスクロールなしで達成できる。

| 部分 | 内容 | 高さ |
| --- | --- | --- |
| 上端 | 1pxの`--line` | 6 |
| R1 直近8件 | Sチップを入れたキーを横スクロール（`scroll-snap`）。空なら「入力した技がここに並びます」（muted） | 44 |
| R2 プリセット1段目 | 4列。236 波動／214 竜巻／623 昇龍／22 下下 | 46 |
| R3 プリセット2段目 | 4列。63214／[4]6 溜め横／[2]8 溜め縦／360 一回転 | 46 |
| R4 システム | 横スクロール。CDR／生ラッシュ／DI／SA1／SA2／SA3／DP／Dリバ／CH／PC | 44 |
| 下段ブロック | 左: 方向3×3（↖↑↗／←N→／↙↓↘）。右: 1段目［立ち｜↓｜J｜消す］、2段目［●P弱｜●P中｜●P強｜OD-P］、3段目［●K弱｜●K中｜●K強｜OD-K］ | 156 |
| 下余白 | ＋`env(safe-area-inset-bottom)` | 6 |

各段の間隔は4、まとまりの区切り（R4と下段ブロックの間）は8。合計368px（360×740の半分370以下）。プリセットの通称は236＝波動、214＝竜巻、623＝昇龍、22＝下下、[4]6＝溜め横、[2]8＝溜め縦、360＝一回転。63214は矢印のみ（通称なし）。

### キー

- 共通: 塗り`--key`、1pxの枠`--line-strong`、`--r-key`。押下中は地を`--line-strong`に変える。選択中（姿勢、ペンディング）は3pxの内側枠`--fg`（`box-shadow: inset 0 0 0 3px`）。塗りの反転は主ボタン専用。
- ボタンキー: 中に●30px。ODキー: 「OD」13px／700の`--od`文字と`--od`の●20pxを2つ重ねる。プリセットキー: 上に矢印列13px（線幅2.5）、下に通称12px（muted）。方向キー: 矢印18px、中央のNは14px（muted）。
- 姿勢キー: ［立ち］は文字、［↓］は矢印、［J］は文字。`role="radiogroup"`、各キーは`aria-checked`を持つ。消すキー: 線画の後退アイコン＋12pxの「消す」、aria-labelは「直前の入力を取り消す」。
- 幅の配分: `grid-template-columns: 140px 1fr`、右側は`repeat(4, 1fr)`、`gap 4px`。430px幅ではボタンが1つ約63px。

### 入力の規則

- 姿勢: ↓かJを押すとペンディングになり、次にボタンを押すと適用されて自動で立ちに戻る（1回限り）。同じ姿勢をもう一度押すと解除。↓の後にモーションを押すと↓は破棄。Jの後のモーションは、ジャンプ中の必殺技として併用できる。
- モーション: プリセットを押すとペンディング中の方向列を置き換える。その後に方向キーを押すと末尾に追記する。
- 方向キー: 押すたびに方向列へ追記。ボタンを押した時点で、方向が1つなら方向入れ通常技、2つ以上なら必殺技になる。方向↓1つ＋ボタンは、しゃがみ通常技として保存する（D-005）。
- OD-P／OD-K: モーションがペンディングならOD必殺技を確定する。モーションがなければ何もせず、トースト「先にモーションを選んでください」を出す（キーの淡色化では示さない）。
- ボタン以外（システム技、直近の技）を押した場合: ペンディングを破棄してから追加する。
- 消す: ペンディングがあれば1つ前の状態へ戻す。なければカーソル直前のトークンを削除する。

### ペンディング表示・カーソル・編集メニュー

- 列のカーソル位置に仮チップを出す。ペンディング中の記号を不透明度60%で描き、続けて塗りのない円（直径34、1.5pxの`--fg-muted`線）を置く。押した姿勢キーには選択中の枠を付ける。
- 挿入カーソルは3×34pxの縦棒、`--fg`、角丸1.5、点滅させない。既定は末尾。末尾以外にあるときは、列の最後に「末尾へ」の文字ボタン（高さ44）を出す。
- チップをタップすると、チップに近接したポップオーバー（既定は上側、入らなければ下側。最大幅320、塗り`--surface`、枠1px`--line-strong`、`--r-key`）を出す。選択中のチップには2pxの`--fg`枠（角丸6）を付ける。中身は、モーションを含む技なら1行目に「↓↘→ ＝ 236（波動）」（muted、12px）、強度の行［弱●］［中●］［強●］（必殺技なら［OD］も。SAなら［SA1］［SA2］［SA3］）、［この前に挿入］［削除］（各44px）。削除は即時に実行し、取り消しトーストを出す。閉じる操作は外側のタップ、戻る操作、Esc。
- 直近8件: そのキャラの保存済み記録から作る。最新順で重複は除き、注記（CH・PC）は含めない。1タップでカーソル位置に追加する。

## 5. 共通コンポーネント

- 上部バー: 高さ48＋`safe-area-inset-top`、塗り`--bg`、下に1pxの`--line`。左に戻る（44×44、線画の‹、aria-labelは戻り先の名前）、タイトル（17px／700、省略表示）、右に補助操作。

- セクション見出しの帯: 高さ44、`position:sticky`、塗り`--surface`。折りたたみの線画（▸／▾、`aria-expanded`）、2桁の番号（`--t-sm`、muted、tabular）、名称（15px／700）、件数（12px、muted）、右に［＋］［…］（各44）。

- トースト: 下部バーの上から16px、塗り`--key`、1pxの`--line-strong`、`--r-key`、文字14px、操作ボタン「元に戻す」（高さ44、700）。`role="status"`、表示は6秒（保存成功は2.5秒）。フォーカスかホバーがある間は一時停止。
- エラー表示（その場に出す。消えない）: 塗り`--key`、左に4pxの実線（`--fg`）、線画の⚠三角、見出し15px／700、本文14px。赤は「強」の意味を持つのでエラーに使わない。
- ボトムシート: 塗り`--surface`、上の角`--r-sheet`、背面`--scrim`。閉じるボタンはシートの下端（親指側）に置く。

## 6. 画面

ルートは`location.hash`で持つ（`#/`、`#/c/ryu`、`#/c/ryu/r/<id>`、`#/c/ryu/r/<id>/edit`、`#/c/ryu/new?s=<sectionId>`、`#/settings`）。シート・ポップオーバー・凡例を開くときは`history.pushState`し、戻る操作でそれらが閉じる。保存後は`location.replace`で詳細へ移る（詳細で戻ると一覧に着く）。

### 6.1 キャラクター選択 `#/`

- 上部バー: 「SF6戦略メモ」、右に［設定］。本体は3列の罫線グリッド（セル110×52、名称15px／700、件数12px muted、0件は非表示）。公式の並び順（D-010）で32件を縦スクロール。
- 「最近使ったキャラ」は下部バーに最大3件（高さ48）を固定する。初めて使うときは出さず、その位置に「キャラクターを選ぶと記録を始められます」（muted）を出す。
- 書き出しの案内（条件付き、surface、主ボタンにしない）: 「最後の書き出しから21日たちました［書き出す］［あとで］」。［あとで］で7日間出さない。

### 6.2 記録の一覧 `#/c/:id`

- セクション見出しの帯の下に、記録の行を並べる。下部バーは［並べ替え］［＋セクション］［＋ 記録］（＋記録が主ボタン）。
- セクションがないとき: 「このキャラクターの記録はまだありません。まず状況（セクション）を作ります。」と、候補（通常、カウンター、パニッシュカウンター、インパクト壁やられ、スタン、画面端、起き攻め）を副ボタンとして折り返して並べ、1タップで追加できる。最後に［名前を付けて作る］。空のセクションには「まだ記録がありません［＋ 追加］」。
- ［…］のシート: 名称変更、上へ、下へ、削除。
- 並べ替え: ［並べ替え］で見出しだけの列になり、各見出しの右に［↑］［↓］（各44）を置く。下部バーは［完了］のみ。移動するたびにライブリージョンで「画面端を2番目に移動」と読み上げる。ドラッグはPhase 1では作らない。
- 削除: 空のセクションは即時に削除し取り消しトーストを出す。中身のあるセクションはシートで移動先をラジオで選び、［移動して削除］で実行する（他にセクションがなければ削除ボタンを無効にして理由を表示、D-005）。確認ダイアログは使わない。
- 折りたたみの状態はキャラごとに保存する。Phase 2で下部バーの左に［絞り込み］、上部バーの直下に種別の切替を追加する。

### 6.3 詳細 `#/c/:id/r/:rid`（閲覧専用）

- 構成は上から、セクション名・位置・タグ（13px muted）、タイトル（17px／700）、余白24、コマンド列（L、画面内で最大の要素）、余白24、メモ（見出し13px muted、本文15px／1.7）。下部バーは［その他…］［複製］［編集］（編集が主ボタン）。上部バー右に［凡例］。
- チップのタップで編集はできない。モーションを含むチップをタップするとポップオーバー「↓↘→ ＝ 236（波動）」を出す。詳細に入力要素（input・textarea・contenteditable）を置かない。
- ［その他…］のシートに［削除］。削除すると一覧へ移り、トースト「『タイトル』を削除しました［元に戻す］」を出す。
- 凡例: 上部バーの［凡例］から高さ90dvhのボトムシートを重ねて出す（画面は移らない）。形 → 意味 → 書き出し時の表記の対応表。グループはボタン（3色、補助文字）、姿勢、方向（8方向、テンキー対応の3×3図）、モーションのプリセットと通称、OD、システム技・SA（正式名称と略称）、注記、▶。下端に固定の［閉じる］。戻る操作でも閉じる。

### 6.4 編集 `#/c/:id/r/:rid/edit`、`#/c/:id/new`

- 上部バー: 戻る、タイトル、右に［凡例］［保存］（保存が主ボタン。ユーザー確認済み）。直下の右寄りに「下書き保存済み HH:MM」（12px muted）。コマンド列（L、仮チップ＋カーソル）。空のときは「下のパッドで技を入力」。その下に、セクション（セレクト）、タイトル（任意）、位置（どこでも／画面端／画面中央）、タグ、メモ。パッドは下部に固定。
- レイアウトは`height:100dvh`の縦flex。入力欄の領域は`flex:1; overflow:auto`、パッドは`flex:none`で`position:fixed`にしない。コマンド列はinputにもcontenteditableにもしない（ソフトキーボードを出さないため）。タイトルやメモにフォーカスするとパッドを隠し、コマンド列の領域をタップすると再び出す。
- 下書き: 変更のたびに`localStorage`へ保存する（キーはD-003の`sf6memo.drafts`内）。開いたときに下書きがあれば上部にお知らせ（新規なら「前回の下書きを開きました［破棄して新規］」）。保存せずに戻ったらトースト「下書きを残しました」。
- 保存: 成功したら詳細へ`replace`で移りトースト「保存しました」を出す。失敗したら画面を移らず、その場にエラーを出す（6.6）。一覧のセクションの＋から来た場合は、セクションが選択済みで始まる。

### 6.5 設定とデータ `#/settings`

- 構成: データ（最後の書き出し日。未実施なら「まだ書き出していません」。［JSONを書き出す］主ボタン、［JSONを取り込む］副ボタンとその下のエラー位置）、表示（方向の表記［矢印｜数字］、ボタンの補助文字［オフ｜オン］と実際のチップでの例示、［凡例を見る］）、非公式表記1行「非公式アプリです。Capcomとは関係ありません。」とバージョン。破壊的な操作は置かない。

### 6.6 状態

| 状態 | 表示 |
| --- | --- |
| 空（キャラ、一覧、セクション、列、直近） | 各画面に記載。必ず「次の1手」のボタンを置く |
| 読み込み中 | `localStorage`は同期処理なのでスケルトンやスピナーは作らない。非同期なのはJSON取り込みの読み込みだけで、その間はボタンの文言を「読み込み中…」にして無効化する |
| 保存済み | トースト「保存しました」。編集画面の上部に「下書き保存済み HH:MM」 |
| 容量不足（`QuotaExceededError`） | 編集画面にその場のエラー「保存できませんでした。端末の保存領域がいっぱいです。入力内容はこの画面に残っています。」と［JSONを書き出す］。下書きの保存失敗も同じ表示 |
| 取り込み不正 | 取り込みボタンの下にその場のエラー。見出し「取り込めませんでした（データは変更していません）」と理由1行（例: 「JSONとして読めません」「schemaVersion 3 には対応していません」「12件目の tokens が不正です」） |
| 取り込み前の確認 | シート「取り込みの確認」。「追加 12件 ／ 更新 3件 ／ 変更なし 40件」と「同じ記録は更新日時が新しい方を残します」。［やめる］［取り込む］。完了後にトースト「取り込みました（追加12・更新3）」 |

## 7. 動き

用途は「入力の反応」と「遷移の方向」だけ。

| 対象 | 動き | 時間とイージング |
| --- | --- | --- |
| キーの押下 | 地の色の即時切り替え。離したときだけ`transition: background 80ms linear` | 押下は0ms |
| チップの追加 | 同じフレームで不透明度1のまま描画し、`scale(.88)→1` | 120ms、`cubic-bezier(.2,.8,.2,1)` |
| 画面遷移（奥へ） | 新しい画面だけ`translateX(24px)`、opacity 0→1。旧画面は即時に消す | 160ms、ease-out |
| 画面遷移（戻る） | `translateX(-24px)`から同様 | 160ms、ease-out |
| シート | `translateY(100%)→0`、背面は0→.6 | 開く200ms `cubic-bezier(.2,.8,.2,1)`、閉じる150ms ease-in |
| トースト | `translateY(8px)`、opacity | 140ms |

動かさないもの: 折りたたみ、カーソル（点滅しない）、仮チップ、ローディング。`prefers-reduced-motion: reduce`では`*,*::before,*::after { animation-duration:.01ms!important; animation-iteration-count:1!important; transition-duration:.01ms!important }`を当てる。

## 8. レスポンシブとアクセシビリティ

- viewportは`width=device-width, initial-scale=1, viewport-fit=cover`（拡大は禁止しない）。上部バー・下部バー・パッドに`env(safe-area-inset-*)`を足し、高さには`dvh`を使う。横持ち・タブレットは本文の最大幅を480pxにして中央に寄せる。`@media (max-height:560px)`ではパッドを縦flexから外し、コマンド列の下に通常の流れで置く。パッドは`touch-action:manipulation; user-select:none; -webkit-touch-callout:none`。
- すべてのキーは`<button type="button">`。日本語のaria-labelを付ける（「弱P」「しゃがみ」「波動 236」「キャンセルドライブラッシュ」）。列のチップには読み上げ用の名称（例:「屈中K」）を付け、▶は`aria-hidden`にして視覚的に隠した「、次、」を置く。追加したトークンを、視覚的に隠した`aria-live="polite"`で「追加: 屈中K」と読み上げる。
- 色だけに意味を持たせない（種類は形、強度は補助文字の設定、選択状態は枠と`aria-checked`／`aria-pressed`）。文字は最小12px。

## 9. アプリアイコン

- 図案は「↓から右へ曲がる太い矢印が●に届く」独自のモチーフ。512の正方形を`#16140F`で全面塗り（maskable対応）、図案は中央320×320（96〜416）に収める。矢印は`--fg`、線幅44、端は`butt`、曲がり角は二次曲線。●は`#F0D870`、直径120程度、中にP（3章と同じ形）を`--ink`で描く。座標の例: 軸`M128 120V240Q128 300 188 300H260`、矢じり`polygon 252,252 300,300 252,348`、●は中心(356,300)・半径60。外接矩形が中央に来るよう全体をy方向に+27移動して調整する。
- 原図は`icon.svg`として置き、そこから`icon-192.png`と`icon-512.png`を1回だけ書き出す。manifestには同じファイルを`purpose:"any"`と`purpose:"maskable"`の2項目で登録する（併記しない）。
- Capcomの画像・ロゴ・フォント・「6」の意匠は使わない。完成後に、公式ロゴを連想させないことと、48dpに縮小しても矢印と●が判別できることを目視で確認する。

## 10. 実装時の注意

- 記号はSVGスプライトで描く。Unicodeの▶・矢印・↻を画面に文字として描画しない。コピーやテキスト書き出しにはUnicodeを使う。
- `localStorage.setItem`はすべて`try/catch`で囲み、`QuotaExceededError`を6.6の表示につなげる。保存に失敗したら画面を移らない。
- ▶の挿入はデータ側の規則で、トークンとして保存しない。CH・PCの直後には挿入しない。ODのトークンは強度を持たない（P・Kの区別だけ）。
- パッドの高さ368pxを確認する。360×740のスクリーンショットで、パッドの上端がy≥372にあることを合否チェックに含める。
- 100ms以内のチップ表示は、追加したチップをその場で描画する前提で、実機で計測する。
- グレースケールの確認（受け入れ基準7.3-7）は、DevToolsの「Emulate vision deficiencies: Achromatopsia」または`filter: grayscale(1)`で撮ったスクリーンショットで行う。
- 未検証: 実機でのフォント表示と描画、アイコンの下書き座標の見た目、コントラスト比（手計算）。
- Phase 3候補: 左手操作用のパッド左右反転、近・遠の表記。
